# Bias & Fairness Assessment — L0-5.2

**Agent:** material-risk-agent
**Status:** Documented. Primary bias surface = supplier-risk scoring. Mitigated by deterministic transparent rules + human approval; residual risk LOW, monitored. Tenant 5.1 Responsible AI evaluation remains the authoritative gate.

Checklist item **L0-5.2** requires evaluation of outputs for bias/fairness with a defined framework, thresholds, and a customer-facing disclosure.

## 1. Where bias could arise

This agent does not act on people or protected attributes. The relevant fairness surface is **commercial**: supplier-risk scoring could systematically disadvantage **chronically-late vendors** and bias purchasing decisions (e.g. flagging ABC Steel Ltd via the chronic-late rule and surfacing an alternative supplier).

Measurement framework: because no protected demographic attributes are processed, demographic-parity / equalized-odds metrics are **not applicable**. Fairness is instead assessed as **procedural fairness** — are vendors scored by transparent, identical, evidence-based rules?

## 2. Mitigations

| Mitigation | Implementation |
|---|---|
| Deterministic, transparent rules | Chronic-late = >=3 of last 4 deliveries late (BR-005); risk bands computed arithmetically, not by LLM judgment |
| Evidence-based, same rule for every vendor | Scoring reads GR history (MSEG/MKPF) identically across suppliers |
| Human approval before any supplier-affecting write | `trigger_escalation_workflow` and `update_po_delivery_date_or_create_expedite_po` are HITL-gated (confirmed=true required) |
| Alternative-supplier visibility gated | Visible to the **Purchase HoD role only** (BR-006) — prevents unsanctioned supplier substitution |
| No protected attributes | Vendor master carries no demographic data; none is used in scoring |
| Advisory-only | Agent never autonomously writes SAP business objects; a human decides |

## 3. Acceptance position

A vendor flagged chronically-late is a **factual, reproducible** read of delivery performance, not a demographic judgment. The rule is disclosed to the user (customer-facing transparency) alongside the underlying deliveries. Pass criterion: every risk/vendor flag is traceable to deterministic inputs the user can inspect.

## 4. Residual risk & monitoring

- **Residual risk: LOW.** Risk = over-reliance on a late-delivery signal that may reflect upstream causes outside the vendor's control (e.g. port congestion, already labelled in the corpus).
- **Monitoring:** re-assess no less than every six months or after any model/prompt change; the human approver is the control point that can override a flag with a logged reason.
- Results archived alongside the tenant **Responsible AI Pre-Release Evaluation (5.1)**, which is the hard gate.
