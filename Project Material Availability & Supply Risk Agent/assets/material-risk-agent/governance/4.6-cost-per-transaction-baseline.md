# Cost Per Transaction Baseline — L0-4.6

**Agent:** material-risk-agent
**Status:** Documented. Transaction = 1 agent invocation; cost components bounded; instrumentation via OpenTelemetry + structured JSON logs. Raw cost data defers to metering (4.2).

Checklist item **L0-4.6** requires cost-per-invocation to be defined and instrumented across LLM, tool, and retrieval operations, with a ceiling threshold set before go-live.

## 1. Transaction definition

**1 transaction = 1 agent invocation** (one user request through to the synthesized advisory response, including any HITL confirmation turn).

## 2. Cost components

| Component | Bound per transaction | Control |
|---|---|---|
| LLM calls | ~2 (orchestration + synthesis), <= 52,000 tokens worst case | temp 0.0; summarization at 30k; fallback empty |
| Tool calls | <= 15 tools (12 read/compute + 3 write) | MCP timeout 30s per call; circuit breaker trips at 3 consecutive failures |
| Retrieval | top-k = 4, similarity gate 0.82 | HANA Cloud Vector Engine; chunks injection-scanned fail-closed + PII-redacted |
| Deterministic core | 0 tokens | pure stdlib arithmetic |

## 3. Ceiling threshold

Ceiling = the worst-case **52,000-token** envelope per transaction. Any transaction exceeding the ceiling triggers a cost review before the next model or tool change is applied. The ceiling is recorded on the go-live checklist.

## 4. Instrumentation

- **OpenTelemetry spans** per step (LLM call, tool call, retrieval), giving step-level latency and the parent/child trace (ties to 6.7 observability).
- **Structured JSON logs** capturing: `prompt_tokens`, `completion_tokens`, `latency_ms`, `tool_name`, `status`, `model_id`.
- Raw per-tenant cost attribution defers to **AI Scenario Metering Integration (4.2)**; customer-facing estimates to **Customer Token Consumption Forecast (4.5)**.

## 5. Review cadence

Baseline reviewed **quarterly** and **on drift** (any 4.2 metering anomaly or 10.3 model-drift alert). No SAP pricing is asserted here — this baseline is a token/latency/call-count instrument; monetary conversion happens via 4.1/4.2 on the tenant.
