# Model Update & Retraining Governance — L0-2.7

**Agent:** material-risk-agent
**Status:** Documented. No training/fine-tuning performed — hosted models consumed via Generative AI Hub. Version pinning active via config/env.

Checklist item **L0-2.7** requires a governance record for any training, fine-tuning, model swap, customer-notification protocol, and rollback procedure.

## 1. Training & fine-tuning position

**No training or fine-tuning is performed.** The agent consumes hosted foundation models (`sap/anthropic--claude-4.5-sonnet`, `sap/anthropic--claude-4.5-haiku`) through SAP AI Core / Generative AI Hub via `ChatLiteLLM`. No customer or project data is used to train or fine-tune any model. Attestation: customer data is used only as inference-time context, never for training.

## 2. Version pinning

| Control | Mechanism |
|---|---|
| Primary / summarization model IDs | Pinned via SAP `agent_decorators` config keys / environment |
| Fallback chain | `config.fallback_models` (empty by default) |
| Circuit breaker | threshold 3 / cooldown 30s, tunable via config |

Any model-ID change is a configuration change subject to the same regression gate as code (ties to 3.4 prompt/config governance and 7.5 regression environment).

## 3. Re-evaluation trigger

A full re-evaluation is mandatory whenever the underlying hosted model receives a provider-side update, safety patch, or infrastructure swap. This ties to **L0-2.5 Ongoing Model Version Re-evaluation** and is the primary consumer of **L0-10.3 Model Drift Detection** alerts. Re-evaluation re-runs the tenant 2.2 benchmarking suite plus this agent's offline regression suite.

## 4. Post-update quality gate

Before a changed model reaches customer production, output quality must be confirmed against a **regression baseline of 7.5** (prior-release pass bar). Any regression against baseline is a release blocker.

## 5. Rollback

Rollback = redeploy the last-known-good configuration (pinned model IDs + prompt templates + tool set). Because models are hosted and stateless, rollback is a configuration redeploy with no data migration.

## 6. Customer notification

Customer notification lead time: **>= 10 business days** before a model-version change reaches their production tenant, with the re-evaluation outcome summarized.

| Event | Action | Lead time |
|---|---|---|
| Provider model update detected | Trigger 2.5 re-eval | immediate |
| Re-eval passes baseline 7.5 | Notify customer, schedule rollout | >= 10 business days |
| Re-eval fails baseline | Block, remediate or rollback | — |
