## 3. Orchestration / reasoning (8.5)
- **Bounded by design:** LLM-orchestrated over a deterministic domain core (all arithmetic in pure Python — "the LLM never computes"); typically ~2 LLM touch-points per interaction.
- **`recursion_limit = 15`** on the LangGraph invocation bounds tool-call loops so a vague query cannot run away (`app/agent.py`).
- Token envelope ≤ 52,000 tokens/run; summarization middleware compresses history past 30,000 tokens (ties to Cost Per Transaction Baseline, L0-4.6).

## 4. Backend / tool-call performance (8.6)
- Per-call OData timeout `30s` (`httpx.Timeout`, `app/s4_client.py`).
- **Hard `$top = 100` cap** on PO and PR reads so an unfiltered query cannot overflow the context window; GR history capped at 4.
- **Request-scoped 30s cache** keyed by `(service, entity, params)` dedupes repeat OData reads within a turn.
- Blocking OData runs in a thread-pool executor (`run_in_executor`) so a slow call never stalls the async event loop.
- Circuit breaker opens after `3` consecutive transient model failures (cooldown `30s`), with an ordered fallback chain.
- Per-tool latency is logged by observability (L0-6.7) and surfaces on the operational dashboard post go-live.
