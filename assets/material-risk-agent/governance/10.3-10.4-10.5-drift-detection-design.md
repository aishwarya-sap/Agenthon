# Drift & Change Resilience Design — L0-10.3 / 10.4 / 10.5

**Agent:** `material-risk-agent`
**Status:** Design + alert thresholds defined — **monitors stand up post-go-live (need production baseline/traffic)**

These three controls are **continuous, deploy-time** loops. They cannot be "green" offline because they require a production baseline and live traffic; this document defines the design, thresholds, and escalation so the monitors can be stood up immediately on go-live.

## 1. Model Drift Detection (10.3)
- **Baseline:** verdict-correctness + risk-band accuracy + intent-routing scores from the L0-2.2 benchmarking run (captured at go-live).
- **Monitor:** periodic re-scoring of a held-out slice of the evaluation set against the live model.
- **Alert threshold:** any metric degrading > 5 percentage points vs baseline → automated alert → triggers Ongoing Re-evaluation (L0-2.5) and the frontier-model gate re-check (L0-2.6). **Loop 1.**
- **Escalation:** AI governance; model rollback per `2.7`.

## 2. Data Drift Detection (10.4)
- **Monitored:** RAG corpus composition (supplier emails / schedules), user-query distribution, retrieved-context distribution, and the live S/4 material/PO mix.
- **Signal:** shift in retrieval scores / similarity-gate pass-rate / query-term distribution beyond control limits.
- **Alert threshold:** gate pass-rate or mean retrieval similarity moving > 10% vs rolling baseline → re-run the RAG Evaluation Scorecard (L0-3.3) via RagEval. **Loop 2.**
- **Escalation:** agent owner; review Document Grounding setup (L0-3.1).

## 3. Architecture Drift Detection (10.5)
- **Monitored:** model-endpoint substitution, tool/ORD version changes, vector schema changes, infra config drift — reconciled against the Dependency Map (`10.2`).
- **Detection:** compare the live deployment manifest to `asset.yaml` `requires[]` ORD IDs on a schedule.
- **Action:** any drift → investigate → either accept with a governance-record update or remediate within SLA. **Loop 3** (re-validate tool-dependent behaviour against the regression env, L0-7.5).

## 4. Post go-live operational governance
- Accuracy degradation (wrong risk band, stale buffer, missed critical-path gap) is a **first-class incident**. Define support tiers, SLA, and incident ownership before customer production (delivery lead).
- All three monitors emit to the operational dashboard fed by observability (L0-6.7).

## 5. Owner
Delivery lead stands up the monitors at go-live; AI governance owns thresholds.
