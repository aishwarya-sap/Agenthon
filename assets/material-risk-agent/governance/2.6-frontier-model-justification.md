## 2. Why a frontier model is required

The agent has exactly **two bounded LLM touch-points per interaction**:

1. **Tool orchestration** — reading an ambiguous natural-language request ("is the Level 3 slab pour at risk?"), selecting from 15 governed tools, and sequencing read/compute calls.
2. **Report synthesis** — turning the deterministic tool outputs into a role-appropriate, citation-grounded advisory narrative with the live/simulated and financial disclaimers intact.

The **deterministic core performs all arithmetic** (net-availability, risk banding, chronic-late detection, SLA math) in pure stdlib Python — 0 tokens, no model involvement ("LLM never computes"). A frontier model is justified only for the language-understanding and synthesis steps, where instruction-following fidelity, refusal discipline (HITL gate, injection resistance), and faithful grounding directly determine advisory safety. A weaker model that mis-sequences a write tool or ignores the confirmation gate is a safety regression, not just a quality one.
