# Model Update & Retraining Governance — L0-2.7

**Agent:** `procurement-bottleneck-agent`
**Status:** Policy defined — activates at go-live

## 1. Training / fine-tuning position
This agent performs **no training or fine-tuning**. It consumes a hosted foundational model through the Generative AI Hub (J17). There is therefore **no customer data in any training step** — attested here and in `5.7-ip-data-ownership-governance.md`.

## 2. Model identity & version pinning
- Primary `sap/anthropic--claude-4-5-sonnet`; fallback `sap/anthropic--claude-3-5-haiku`.
- The deployed version is pinned via `AGENT_MODEL` / `AGENT_MODEL_FALLBACK` environment variables (see `.env.example`), never hard-coded, so a change is a tracked configuration change.

## 3. Trigger for re-evaluation (ties to L0-2.5 / L0-10.3)
A full re-benchmark (L0-2.2) against `eval/eval_dataset.jsonl` is **mandatory** before any of the following reaches a customer tenant:
- provider-side model update or safety-tuning patch
- fallback-chain change
- inference-infrastructure swap
- a Model Drift Detection alert (L0-10.3) firing against the production baseline

## 4. Rollback
- Revert `AGENT_MODEL` to the last-known-good pinned version and redeploy (`cf push`); the deterministic core is model-independent, so rollback affects only the two language touch-points.
- Rollback must be exercised in the regression environment (L0-7.5) before go-live.

## 5. Customer notification
- Lead time and protocol for notifying the customer of a model change: **owned by the delivery lead**; minimum 10 business days for a major-version change unless a safety patch requires faster action.

## 6. Post-update quality gate
Output quality must be confirmed against the regression baseline (L0-7.5) before full rollout; a quality regression on verdict correctness or disclaimer enforcement is a release blocker.
