# Cost Per Transaction Baseline — L0-4.6

**Agent:** `procurement-bottleneck-agent`
**Status:** Baseline design complete — **live instrumentation on deploy**

## 1. Definition
One "transaction" = one agent invocation (a full critical-path analysis, with or without the subsequent approval turn). Cost per transaction = LLM token cost + tool-call cost + retrieval cost.

## 2. Cost components
| Component | Driver | Bounded by |
|---|---|---|
| LLM | 2 calls/run, ≤52,000 tokens/run | `config.TOKEN_BUDGET_PER_RUN` |
| Tool calls | ≤13 tools, reads only | per-tool timeout `config.TOOL_TIMEOUT_SECONDS=30`, circuit breaker after `CIRCUIT_BREAKER_THRESHOLD=3` |
| Retrieval | 1 RAG call, top-k=4, gate ≥0.82 | `config.RAG_TOP_K`, `RAG_SIMILARITY_GATE` |

Because the quantitative core is deterministic Python, the dominant cost is the two LLM calls; token cost is bounded by the enforced ceiling.

## 3. Ceiling threshold
- Ceiling = cost of a worst-case 52,000-token run (compute from LLM Calculator rate, L0-4.1).
- Any measured cost/transaction exceeding the ceiling triggers a cost review **before** the next model or tool change is promoted (ties to L0-2.7).

## 4. Instrumentation (already wired; reports on live)
`app/observability.py` emits per-run structured fields including `prompt_tokens`, `completion_tokens`, `latency_ms`, `tool_name`, `status`. On the tenant these feed:
- AI Scenario Metering Integration (L0-4.2) for raw cost
- the operational dashboard (L0-6.7 / L0-10.7)

## 5. Review cadence
Recorded in the go-live checklist and reviewed quarterly, or on any drift alert (L0-10.3/10.4).
